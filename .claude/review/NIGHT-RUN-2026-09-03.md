## 3. Vertical (portrait) video — editor, simulations, share, export

### The ask
If the base video is portrait (e.g. 1080×1920), everything is portrait: no smart crop, the editor
timeline and preview, every simulation, the share pages, and the export — which must be 1080×1920.
Rotating the phone never changes it. A "shorts" edition of the product for that kind of video.

### What the map found (agent survey, file:line in the run transcript)
- **Source dimensions are never stored.** `video_files` has no width/height; the only probe that
  reads them is inside the crop job and its answer never leaves the crop JSON. This is the root gap.
- **The export graph is already grid-parameterised** — one constant, `EXPORT_GRID` in
  `services/export/types.ts:33`, frozen into the plan at `exportPlan.ts:700`. ffmpeg chains, the
  capture spec, the assembler gate, the level check all flow from `grid`.
- **HLS is hard 16:9**: `HLSTranscoder.ts:30-34` `TIERS` are 640×360…1920×1080, so a 1080×1920
  upload is pillarboxed into 1920×1080 — the picture is delivered at 608×1080 inside a 1080p stream.
- **The crop subsystem assumes a landscape source**: analysis squeezes into 320×180, keyframes
  degenerate to x=0.5 for a portrait source, and `useCropOverlay.ts:186-189` detects "portrait" from
  the *device*, then applies `object-fit: cover` — which would crop the top and bottom off a portrait
  source on a portrait phone. There is no per-project disable.
- **Simulations are aspect-agnostic at runtime** (fill their box, re-layout on resize) but poster
  identity hardcodes `aspect:'wide'` in `buildPlayerConfig.ts:396-400` and `exportPlan.ts:415-435`.
  `SimAspectProfile` already has `'portrait'` and `POSTER_SIZES.portrait` (720×1280) is defined.
- **Editor preview follows the browser window's aspect**, not the project's (`VideoEditor.tsx:999-1008`).
  Timeline filmstrip stretches frames into 80×45. The public lesson page wraps the player in
  `aspect-video`; every full-bleed viewer is already device-shaped and fine.
- Generated b-roll (Kling/Seedance/Veo) and AI thumbnails are hard 16:9 / landscape.
- Phone footage often carries a rotation tag on a landscape-coded stream; ffmpeg autorotates on
  decode, so the probe must apply the tag to report the *displayed* orientation.

### Design
1. **Persist source geometry (migration 082).** `video_files.width`, `height` (int, nullable), written
   by `probeMediaInfo` (extended to `width,height,sample_aspect_ratio` + rotation side data) in
   `runVideoTranscode`, and seeded at upload from the browser's `videoWidth/videoHeight` exactly as
   `duration_sec` is seeded. Null = unknown = landscape (every existing row).
2. **One derived truth: `orientation`.** A pure function in `shared/src/video/orientation.ts`:
   `orientationOf({width,height}) → 'landscape'|'portrait'` (portrait iff height > width; square is
   landscape). Project orientation = orientation of the primary (non-b-roll, earliest) ready video.
   Exposed on the project API and in the player config as `orientation`. `projects.format` stays
   untouched (write-only legacy column; overloading it would be a second truth).
3. **HLS ladder per orientation.** `TIERS` becomes `tiersFor(orientation)`: portrait
   360×640 / 480×854 / 720×1280 / 1080×1920, same names (short side), same profiles/levels.
   Landscape output is byte-identical to today, so existing rows and the `hls_*_key` naming survive.
4. **Export grid per orientation.** `exportGridFor(orientation)`: landscape 1920×1080@30 (unchanged),
   portrait 1080×1920@30. `exportPlan` freezes the project's grid; the assembler gate already checks
   `v.width/height` against `grid`. H.264 level 4.0 covers 1080×1920 (same macroblock count).
5. **Crop is skipped for portrait sources.** `runCropAnalysis` returns early with
   `crop_status='none'` (existing vocabulary) and a log line when the source is portrait; the player
   config emits `crop_url: null` for portrait projects; `useCropOverlay` additionally refuses to apply
   `cover` when the source is not landscape (belt and braces — the hook must never crop a portrait
   source). Settings panel hides "Smart Crop" for portrait projects.
6. **Editor preview + simulations at the project's aspect.** `previewAspect` derives from
   `orientation`, not the window; the sim overlay fills that box, so every simulation is authored
   and previewed at 9:16. The sim-generation prompt receives a one-line viewport hint for portrait
   projects. Poster identity uses `aspect:'portrait'`/`aspectProfile:'portrait'` in both
   `buildPlayerConfig` and `exportPlan` (they move together; production has 0 poster rows, so no
   identity migration).
7. **Timeline filmstrip** draws frames with an aspect-preserving fit into a 45px-tall cell whose width
   follows orientation (80 or 26).
8. **Share/public:** lesson page player island uses `aspect-[9/16]` for portrait; library/playlist
   tiles keep their frame but `object-contain` a portrait banner; viewers unchanged (already
   device-shaped).
9. **Generators follow orientation:** b-roll providers get `9:16`; AI thumbnail size 1024×1536.
10. **Backfill:** `scripts/backfill-video-dimensions.ts` (operator-run, `--dry-run` first) probes
    existing `ready` videos through a presigned URL and fills width/height; until it runs, rows are
    landscape by default, which is what they were treated as before.

### Files (central)
`backend-api/src/db/schema.ts`, `db/migrations/082_video_dimensions.sql` (+ rollback, both registries),
`services/video/HLSTranscoder.ts`, `services/video/runVideoTranscode.ts`, `services/export/types.ts`,
`services/export/exportPlan.ts`, `services/buildPlayerConfig.ts`, `services/crop/runCropAnalysis.ts`,
`controllers/v1/video.controller.ts`, `shared/src/video/orientation.ts`, `shared/src/generated/client-v1.ts`,
`client-web/components/VideoEditor.tsx`, `TimelinePanel.tsx`, `VideoUploader.tsx`,
`components/viewer/useCropOverlay.ts`, `ProjectSettingsPanel.tsx`, `app/c/[courseSlug]/[lessonSlug]/page.tsx`.

### Acceptance
- A 1080×1920 upload transcodes to a portrait ladder whose 1080p rendition is 1080×1920 (ffprobe).
- `orientation:'portrait'` in the player config; `crop_url` null; no crop job enqueued.
- Editor preview box is 9:16 on a landscape monitor; a simulation section fills it.
- Export plan grid is `{1080,1920,30}`; the real-encode suite proves the master is 1080×1920.
- Landscape projects: every existing test passes unchanged (byte-identical HLS args, same grid).
- Rotated-tag footage (1920×1080 + rotate 90) is detected as portrait.

### Tests
Unit: `orientation.test.ts` (incl. rotation), `hlsTranscoder.test.ts` gains the portrait matrix,

## 4. Podcast — hands-free car mode

### The ask
Redesign the listening experience for the car: phone, portrait or landscape, minimal text, exact
Spotify / voice-assistant feel. While the episode plays, the listener just talks: the player detects
speech, pauses, listens, answers in real time from the project's context (as the avatar does), and
after a few seconds of silence resumes from where it paused. Minimal controls: pause, stop, a
Spotify-like timeline bar, and an Ask button that works as a physical alternative to speaking.

### What the map found
- The listener page is `/{slug}/audio` — a single fixed 672px column, native `<audio controls>`,
  everything `text-sm`, zero responsive rules, no safe-area handling, no viewport config.
- "Raise your hand" exists but is a **textarea**; the answer is **text**; nothing is spoken; playback
  never pauses. No microphone, VAD, MediaRecorder or speech API exists anywhere on the surface.
- The backend already has every metered piece: Groq Whisper STT (`transcribeAudioFile.ts`, spend
  recorded), `ListenerQuestionService` (records the question first, takes the ±90s/30s transcript
  window around `position_ms`, answers on the utility tier, 20/day/project cap, enabled iff the
  project is public), ElevenLabs TTS (`GuidanceTTSService`, spend recorded). None are wired to voice.
- The only realtime voice loop is the Anam avatar (vendor WebRTC, video-priced) — wrong tool for audio.
- `editions/` is unknown to the media-access layer, so local dev cannot play the edition at all
  (401 on local disk, 403 on R2). Only production's Supabase presign works. This blocks testing.
- The approved design of record (`PARKED-DESIGNS.md` P3-B item 3/4, `INTERACTIVE-PODCAST-PLAN.md`
  §3.3/§5) specified exactly this: voice barge-in and a screen-never Hands-Busy mode. Never built.

### Decision — architecture
**Chained pipeline, on-device VAD, no new vendor.** The owner asked for voice-activated listening
(not push-to-talk). The plan document chose push-to-talk to avoid a VAD false-trigger money leak on a
*cloud* VAD; an **on-device** VAD costs nothing per trigger, so the leak does not exist. Pipeline:

```
mic (getUserMedia, echoCancellation:true)
  → Silero VAD v5 in the browser (@ricky0123/vad-web, ISC; onnxruntime-web, MIT; model MIT)
  → speech start: pause playback within one frame, play a short earcon, ring pulses
  → speech end (VAD): PCM → 16 kHz WAV → POST /api/v1/public/audio/:slug/voice-question
       server: Groq Whisper STT (metered) → ListenerQuestionService (same cap, same context window,
               same record-before-answer order) → ElevenLabs TTS (metered) → { text, audio (mp3) }
  → play the answer through a second <audio> element (so Media Session / lock screen keep working)
  → answer ends → 3 s of silence → resume the episode at the paused position
  → the listener speaks again during the answer → the answer stops, new capture (barge-in)
```
Why not OpenAI Realtime / ElevenLabs Agents tonight: both add a vendor path, a WebRTC client, a new
ledger table and a new abuse surface for ~1 s of latency gain. The chained path answers in ~2–4 s,
masked by the pause + earcon, reuses every rail the wallet-protection design already has, and the
client state machine is transport-agnostic — a realtime tier can sit behind the same button later
(recorded as the ruling on the podcast plan's §7 decisions 2 and 8).

Echo: AEC in `getUserMedia` cancels audio the browser itself plays through `<audio>` elements, and
playback is paused on speech start anyway; a 250 ms minimum-speech rule filters transients.

### Design — UI (`AudioEditionPlayer` rewritten as a car-mode player)
- Full-viewport dark surface, `100dvh`, `viewport-fit=cover`, safe-area insets, no page chrome.
- Portrait: artwork (project thumbnail) → title (one line, large) → progress bar with elapsed/remaining
  → transport row `[⏮ chapter] [⏯ 88px] [⏭ chapter]` → `[🎤 Ask]` big round button + `[■ Stop]`.
  Landscape: artwork left, the same stack right. All targets ≥ 56 px; text only the title and times.
- Voice state ring around Ask: idle / listening (pulsing) / thinking / speaking; one-word status.
- Ask button: tap = start capture now (push-to-talk alternative); tap while answering = stop the
  answer and resume; long-press = toggle hands-free listening off/on (persisted in localStorage).
- Chapters, "Save for the drive", the typed question, and the caption transcript move into a swipe-up
  sheet; nothing in the main view requires reading.
- Keeps: plain `<audio>` (never WebAudio for the episode), Media Session actions. (A `?t=` resume never existed on this page — the ISR route reads no search params; recorded as not-a-regression.)
- First visit: one-line hint under the button; microphone permission asked only when hands-free is
  turned on or Ask is tapped, never on load.

### Design — backend
- `POST /api/v1/public/audio/:slug/voice-question` (multipart: `audio/wav` ≤ 2 MB / ≤ 30 s,
  `position_ms`, `language`): STT → the existing question path → TTS; returns JSON
  `{ status, question, answer, audio_base64? , message }`. Rate limit 6/min per IP, the project's
  daily cap shared with typed questions, bounded temp file, spend recorded for STT and TTS.
- The `editions/` prefix is added to `mediaKeyScope` / `resolveProjectForKey` so local dev and R2
  can serve editions (the testing blocker).
- Shared types for the listener page and the question API in `shared/src/audio/listener.ts` so the
  contract stops living in two hand-written places.

### Files (central)
`client-web/components/audio/AudioEditionPlayer.tsx` (rewrite — the car-mode player lives here; no separate
`CarModePlayer.tsx`), `components/audio/useVoiceLoop.ts` (the VAD wiring lives here; no separate `vad.ts`),
`lib/voiceLoop.ts` (the reducer), `lib/wav.ts`, `lib/audioEditionApi.ts`,
`app/[slug]/audio/page.tsx` (+ `viewport`), `public/vad/*` (worklet + onnx + wasm, MIT/ISC),
`backend-api/src/controllers/v1/audioEdition.controller.ts`, `services/audio/VoiceQuestionService.ts`,
`services/storage/mediaToken.ts`, `services/storage/mediaAccess.ts`, `shared/src/audio/listener.ts`.

### Acceptance
- On a phone-sized viewport, the page shows artwork, title, bar, three transport buttons, Ask, Stop —
  and nothing else above the fold; works in both orientations; lock-screen controls still work.
- Speaking while playing pauses playback within 100 ms and captures until silence; the spoken answer
  plays; playback resumes after 3 s of silence from the paused position.
- Tapping Ask captures without speaking first; tapping during an answer stops it and resumes.
- A silent listener costs $0; every voice question records STT and TTS spend; the 20/day cap and the
  per-IP limit refuse with a spoken-free, glanceable state.
- Local dev can play an edition (the `editions/` access fix).

### Tests
Unit: voice-loop state machine (pure reducer, every transition incl. barge-in and cap-refusal),
WAV encoder, `VoiceQuestionService` (order: record → STT → answer → TTS; failure leaves `failed`
without `answered_at`), controller limits, media-access `editions/` scope. Component: car-mode
render in both orientations, Ask/Stop behaviour with a fake loop. No vendor calls in tests.

## 6. Import gallery full-screen, simulation posters, library speed

### What the map found
- The import gallery is a 1120×760 panel over a dimmed editor, 210px cards, **every card a live
  sandboxed simulation** (no posters exist), one `listSimulations` request per project fanned out
  and awaited together, sequential imports.
- **`sim_posters` holds 0 rows in production.** Nothing generates posters on publish/import; the only
  capture path is an operator canary script. Library tiles therefore show a gradient with a sparkle.
- The worker image has **no Chromium** (only the isolated export-worker image on the GPU host has
  `chrome-headless-shell`), and the export design deliberately runs untrusted sim code only inside a
  network-less container — so server-side poster capture on the VM would violate the isolation rule.
- Full-screen open: `/sim-public/*` text assets are fetched from S3, sha1-hashed and brotli'd **per
  request** with `Cache-Control: no-cache` on non-revision keys; the overlay's "Loading…" cover clears
  on iframe `load`, not on first paint; poster images (when they exist) take two hops (302) at
  `max-age=3600` despite being immutable; tiles have no `sizes`/dimensions and would download 1280×720.

### Design
1. **Posters captured in the creator's browser, through the authoring channel.** The boot snippet
   already injected into every served sim document gains a `SNAPSHOT` request: after gate v5 reports
   `SIM_PAINTED`, inside the wrapped rAF turn (so a WebGL buffer is still intact), it draws the
   largest visible canvas — or, for DOM sims, an SVG `foreignObject` serialisation — into an
   offscreen canvas letterboxed to the requested profile (1280×720 wide / 720×1280 portrait, plus
   the compact size) and posts PNG data URLs back. The editor requests one whenever it previews a
   served revision that has no poster for the current identity (throttled, once per revision) and
   uploads via `POST /projects/:id/simulations/:simId/poster` → `PosterService.storePoster` +
   `invalidate()` (the ledger's pairing invariant). PNG signature + IHDR dimensions validated
   server-side; ≤ 2 MB per rendition; creator-only. A "Refresh banner" button in the section editor.
   Server-side capture on the isolated export host is recorded as the future durable path.
2. **Import gallery = full-screen surface.** `fixed inset-0`, its own header (search, project pills,
   sort), a responsive grid `minmax(300px,1fr)` with 16:9 (or 9:16) poster tiles, live preview only
   on hover/tap ("play" affordance) and full-screen on expand; sticky footer with the Import CTA and
   count. One new endpoint `GET /api/v1/simulations/importable` returns every ready sim across the
   user's editable projects with `poster_url` in one query (replaces the N-request fan-out);
   imports run with bounded concurrency (3).
3. **Library + full-screen speed.** Poster keys are content-addressed, so `getSimPublicUrl` returns
   the bucket URL directly for `/posters/` paths (no API hop; `immutable` honoured); tiles load the
   `compact` rendition with `width/height/sizes`; the overlay shows the poster immediately and
   clears the cover on `SIM_PAINTED`; the entry document is `<link rel=prefetch>`ed on pointerdown.
   `/sim-public/*` text responses get an in-process LRU `{bytes, etag, servingFacts}` cache (60 s,
   bounded by bytes) so a repeat load costs no S3 GET, no sha1, no brotli — ranked fix #3 of the
   scalability investigation and D2 option (a).

## 7. Scale — storage and infrastructure decision

### Verdict (grounded in the code map and the 2026-08-15 investigation, re-checked tonight)
**Keep Supabase Postgres. Move public bytes to a zero-egress, CDN-fronted object store. Take the
app tier off the byte path.** Reasons, each verifiable in the repo:

- Postgres is not the constraint: 28 fixed connections (10+4 per process), every hot path
  index-covered, the pooler costs one env var. Migrating 61 tables / 81 migrations would move the
  database and leave a 2-vCPU box doing the same work. The remaining DB issues (hot `view_count`
  row, per-request `users` write, four unretained tables) are application design and travel with
  any vendor.
- **Egress is what scales with viewers, and Supabase charges for it** while Cloudflare R2 charges
  $0 egress ($0.015/GB-month storage, verified 2026-09-03 on the R2 pricing page). HLS segments,
  posters, sim packages and public audio editions are the bytes viewers pull; on R2 behind a custom
  domain they cost storage only, and R2 serves `text/html` correctly, which deletes the reason the
  `/sim-public` text proxy exists.
- The single VM with no CDN in front of the app is the next ceiling; it is a placement question
  (CDN + cache headers), not a vendor question.

### Phase 1 — tonight, code only, safe on the current stack
1. `/sim-public` in-process cache (with §6) and direct bucket URLs for posters.
2. `prepare: false` on the app pool (D10); guard `QUEUE_PGBOSS_LISTEN` against a transaction pooler.
3. Cache `resolveSimPoolMode` / `resolveSimRuntimeFlags` for 10 s (copy `resolveRumSampleRate`).
4. Debounce `users.last_seen_at` to once per 5 minutes per user.
5. Explicit `Cache-Control: no-store` on player-config / share / permalink / authenticated JSON, and
   `public, max-age=60, s-maxage=60, stale-while-revalidate=300` only where already intended — the
   header discipline a CDN in front of the API requires.
6. Bound the playlist `buildPlayerConfig` fan-out (concurrency 4) and cap `GET /projects` at 500
   with the same response shape.
7. Retention sweep for `branch_path_events` (90 days, modelled on `reapRumEvents`); the orphan blob
   sweeper runs every 6 h, not only at startup.
8. Per-IP rate limit on the public viewer read paths (generous: 120/min) with the in-process
   limiter, documented as per-process.

### Phase 2 — the migration runbook (needs the owner's Cloudflare account; not executed tonight)
1. Run the storage census (`deploy/scripts/storage-census.sql`) — the size decides the copy window.
2. Create the R2 bucket + custom domain (`media.<domain>`) with CORS for the app origins and
   Cloudflare cache rules: `immutable` for `hls/`, `posters/`, revision keys; `no-store` default.
3. Make `R2StorageAdapter.getPublicUrl` return the custom-domain URL (the `/hls-proxy` detour exists
   only because r2.dev CORS was unverified) and make `keyFromPublicUrl` reverse both vendors' shapes.
4. `rclone sync` Supabase → R2 (public prefixes first), then rewrite the URL-bearing columns
   (`corpora.storage_url`, avatar face URLs, guidance URLs) with a resumable, `--dry-run`-first script.
5. Flip `STORAGE_BACKEND=r2` in a release; keep Supabase Storage read-only for 30 days; delete after.
6. Put Cloudflare in front of `app.` and `api.` (proxy mode) once Phase 1's cache headers are live.

### Phase 3 — horizontal app tier (later)
Next.js `output:'standalone'` + nginx-served static; a second API container behind nginx; the
limiter to a shared store; metrics export. Recorded, not scheduled.

Each item is one PR from a short-lived branch, merged with a merge commit as soon as CI is green, so

item ships the parts that are complete, records exactly what was left out in the ledger, and the
run moves on — scope is not silently narrowed.

## 10. Open-source and third-party code policy (binding on every agent and session)

Written into `.claude/reference/stack.md` §8 (every agent reads that file first), `PROTOCOL.md` hard
rules, `review-fixer.md` (the only writer), and `CLAUDE.md` §8.

- **Allowed in shipped code, models, and assets:** MIT, ISC, BSD-2/3-Clause, Apache-2.0, 0BSD,
  Unlicense, CC0, Zlib, PostgreSQL, MPL-2.0 (file-level, unmodified files, licence notice kept),
  CC-BY-4.0 for assets with attribution.
- **Forbidden in anything we ship or run in production:** GPL-2/3, AGPL, LGPL (unless dynamically
  linked and unmodified — ask), SSPL, BUSL/"source-available", Commons Clause, Elastic, CC-BY-NC /
  ND, "research only" / "non-commercial" model weights, and any repository with no licence file.
  Named traps already met in this repo: Ultralytics YOLOv8 (AGPL), InsightFace/SCRFD weights
  (non-commercial), ffmpeg GPL builds are fine as a separate process but never linked.
- **Rules:** read the LICENSE before copying a single line; record the package/model and its licence
  in the PR body; never vendor code without its licence text beside it; a snippet from a blog or an
  answer site is copied only if it is trivially re-derivable, otherwise rewrite it; when unsure,
  do not use it and say so in the PR.
